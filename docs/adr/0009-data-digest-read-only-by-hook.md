# data-digest is read-only by hook, over connector reads declared in Project config

data-digest's connectors are the operator's own MCP servers and CLIs, so the plugin can't name their tools in the agent's `tools:` list (it takes exact names or known server names), and plugin agents ignore `hooks`, `mcpServers` and `permissionMode` frontmatter. So data-digest has no `tools:` list: it inherits the session's tools minus `disallowedTools` (Edit, NotebookEdit, the Harness browser), and the plugin's PreToolUse guard, which runs on every tool call and keys on `agent_type`, is the allowlist. data-digest may use Read, Grep, Glob, WebFetch, WebSearch, ToolSearch, Skill and TodoWrite unchecked; its Bash gets live-verifier's read-only allowlist without the fixture reset; an MCP call passes only on a server listed under `## Data connectors`, any tool of a `read-only` one but only the listed `reads:` of a `read-write` one, and a connector CLI passes on the same terms; a Write passes only if it creates a new `.csv`, `.tsv`, `.json`, `.jsonl`, `.ndjson` or `.txt` file outside hidden directories; every other tool is denied. The hook can't see the caller's extract path, so "only to the caller's path" stays an instruction: what is enforced is that an extract never overwrites a file, never lands in a hidden directory (`.git`, `.claude`, `.github`) and is never code. A new data-typed file can still be one that tools read as config (a nested `package.json`); we accepted that rather than keep a list of config file names. The operator declares reads per connector (an optional `; reads:` suffix on the connector line, which live-verifier's Bash honours too) because tool names don't reliably say whether they write: `graphql_query` can run a mutation and `run_report` only reads. We rejected guessing reads from verbs in tool names (a denylist in disguise), using only connectors marked read-only (the systems worth digesting are usually read-write), and a read-only instruction with no enforcement (the point is that data-digest is safe to delegate to freely). The cost: a read-write connector without `reads:` is unusable to data-digest until setup adds them, and the guard's shell wrapper now starts on every tool call in every session (it exits at once unless the input names a read-only subagent or the Harness browser).
