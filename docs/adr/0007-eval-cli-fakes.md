# Eval CLI fakes live in one shared directory, run by path, with ticks for time

Evals stand in for CLIs such as `gh` with one canonical fake per CLI in `plugin/evals/fakes/`, tested by its own script; each case's scaffold copies the fake from `../fakes/` into the workspace (`.fake-gh/bin/gh`) and writes a canned scenario beside it, and the case's `append_system_prompt` tells the agent to run the fake by that path. The runner gives no way to put a fake on the agent's PATH: `execution.env` accepts only `EVAL_*` keys, the inherited PATH already holds the real CLI, project settings in the workspace aren't loaded, and writing shell rc files into the run's home would edit the operator's real ones if a runner ever stopped redirecting HOME. Scaffolds run from their own case directory, so the copy needs no runner support, and it fails the case loudly if the shared fake isn't there. A long run is faked with ticks instead of wall-clock time: every status read advances the scenario one step, so a case can grade several status updates with a five-second polling interval. We rejected a checked-in copy of the fake in every case directory (copies drift) and a generator script each fixture sources (the same `../` read, with more indirection).
