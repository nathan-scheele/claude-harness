# Project config is a fixed-section markdown document with explicit `none` and `unset`

Project config (`docs/agents/harness.md`) is a markdown document in the Base layer's agent-docs style with nine fixed `##` sections (Code host, Pre-flight, CI, Merge, Deploy, Dev and sandbox, Fixtures, Data connectors, Issues) holding `**Key**: value` lines or plain lists; the template lives in the setup-harness skill (`plugin/skills/setup-harness/project-config.md`). Skills read values by section heading and key, so section names are a contract: renaming one is a breaking change for every skill that reads it. Every value is either real, `none` (the repo deliberately has none, e.g. no dev targets means every target is live) or `unset` (the operator didn't know); a skill that needs a missing or `unset` value stops and points the operator at `/harness:setup-harness` instead of guessing. We rejected a YAML or JSON file because the Base layer's per-repo docs are prose markdown the operator edits by hand (ADR 0001), and rejected free-form prose because several skills need to find the same values reliably. Detection lives in a read-only script (`detect.sh`) with its own tests, so the fiddly parsing (remote URL forms, workflow jobs, package scripts) is deterministic and the skill only judges what the script can't. Setup previews the whole document and waits for the operator's confirmation before writing; an operator request that already says to write once shown counts as that confirmation, because the file is a local, reviewable doc rather than a Live write.
